[3] FORM LOGIN (homepage, action="https://satoshifaucet.io/auth/login")
----------------------------------------------------------------
Field lengkap:
  wallet            : (input email) FaucetPay email — NAMA FIELDNYA "wallet", bukan "email"
  csrf_token_name   : token CSRF CodeIgniter, contoh 25f4e63922c7eb2cf7dc67992311b414
                      (harus di-scrape tiap sesi, berubah-ubah)
  ls                : honeypot field (nilai acak, contoh "kfw7Uevi")
  uf                : honeypot field (kosong)
  utt               : honeypot field (timestamp-ish, contoh "1794381054")
  captcha           : pilihan captcha dari dropdown (hidden) -> "adslab"
  alcaptcha-response: token hasil AdsLab Captcha (di-inject JS setelah solve)

CATATAN ANTI-BOT:
  - ls / uf / utt kemungkinan honeypot / fingerprint antara.
    Automasi harus mempertahankan nilai asli yang dirender server,
    TIDAK mengosongkan / mengubah nilai yang sudah ada (kecuali uf
    yang memang dirender kosong).
  - CSRF wajib fresh: GET homepage -> ambil csrf_token_name ->
    kirim di POST login yang sama sesi cookie.

[5] FLOW ADSLAB CAPTCHA (widget.js v=1 — dibedah dari source)
----------------------------------------------------------------
5.1 Widget di-inject oleh https://adslab.me/api/v1/alcaptcha/widget.js?v=1
    Init otomatis untuk semua elemen .alcaptcha / .adslab-captcha
    yang punya atribut:
      data-sitekey = sitekey publik site
      data-subid   = opsional, default "widget_user"
5.2 UI: kotak 300x100px "press & hold" dengan progress circle.
    User tahan tombol ~beberapa detik (fungsi startHold/completeHold,
    animasi stroke-dashoffset 0.1s linear).
5.3 Setelah hold selesai -> muncul iframe challenge:
      https://adslab.me/alcaptcha?sitekey=<sitekey>
                              &domain=<hostname parent>
                              &subid=<subid>
    (domain parent otomatis = window.location.hostname, jadi
     request HARUS tampak datang dari satoshifaucet.io)
5.4 Challenge di dalam iframe (potongan script iklan juga aktif:
    sads.adsboosters.xyz — model captcha ini berbasis interaksi iklan)
5.5 Selesai -> iframe kirim postMessage ke parent: { token: ... }
5.6 Widget menulis token ke hidden input:
      <input name="alcaptcha-response" value="<token>">
    + dispatch CustomEvent "alcaptcha-success"
5.7 Token ini yang divalidasi server saat POST /auth/login.

IMPLIKASI AUTOMASI:
  - TIDAK kompatibel dengan solver Turnstile现有 (gi7ltc/gi8 Railway).
  - Perlu solver baru berbasis puppeteer-real-browser yang:
      a) buka halaman host dengan domain benar (atau intercept
         navigasi seperti turnstile.js, tapi iframe adslab cek
         "domain" param = hostname parent),
      b) auto "press & hold" (mouse down + tunggu ~3-5 detik + up),
      c) tunggu iframe/postMessage token, ambil alcaptcha-response.

[8] KESIMPULAN & REKOMENDASI
----------------------------------------------------------------
1. Automasi HTTP murni (pola pandax9) TIDAK cukup untuk
   satoshifaucet.io karena:
   a) Captcha AdsLab butuh browser (hold + iframe challenge).
   b) Halaman claim dibalik Cloudflare Managed Challenge
      (butuh browser utk dapat cf_clearance).
2. Jalur automasi realistis: puppeteer-real-browser FULL page
   (mirip pendekatan app.js/turnstile.js) yang:
   - buka homepage asli (bukan intercept) agar domain/sesi CF benar,
   - isi email, hold captcha, tunggu token, submit,
   - halaman /faucet: biarkan browser melewati CF challenge,
   - claim di dalam browser.
3. Risiko tinggi: kebijakan NO PROXY + auto-ban multi-account
   -> 1 akun = 1 fingerprint/IP residential; skala kaki akan
   cepat terdeteksi dibanding pandafaucet.
4. Sitekey AdsLab saat analisa:
   lA0LtcfCXUxnBWifcQrqRsmPi6sSV3HtrpyRodRg
   (format beda dgn Turnstile; jangan pakai regex 0x4AAAA utk site ini)
5. Field-form regex ekstraksi yang robust:
   csrf_token_name\s*=\s*["']([0-9a-f]{32})["']
   name="wallet"\s*  (bukan name="email")
   data-sitekey="([0-9A-Za-z]{20,64})"

[9] UPDATE HASIL EKSPERIMEN LOGIN (11 Nov 2026) — script satoshifaucet.py
----------------------------------------------------------------
Yang SUDAH LOLOS:
  1. GET / -> csrf_token_name + ci_session cookies        : OK
  2. Fingerprint check -> simulasi cookies+field:
     uf  = visitorId hex-32 (FingerprintJS v4 open-source,
           dihitung LOKAL di browser, tak bisa divalidasi server)
     utt = timezone (Asia/Jakarta)                        : OK
     ls  = languages (id-ID,id,en-US,en)                  : OK
  3. AdsLab captcha solved via Tertuyul API
     (method=adslab, pageurl trailing slash)              : OK (~20 detik)
  4. POST /auth/login -> 303 (form valid, captcha valid)  : OK

BLOKIR TERAKHIR:
  Server menolak dengan pesan "VPN & Proxy Detected!"
  -> Bukan bug script. IP user (AS58821 PT Lintas Jaringan Nusantara,
     Jambi, ID) diklasifikasi hosting=true oleh database reputasi IP
     (dites: ip-api.com hosting=true, meski proxycheck/scamalytics bilang
     bersih). Faucet sites lazim memblokir kelas IP hosting/datacenter.
  -> CATATAN: script sama sempat dapat 2 error berbeda:
     - kirim ls/uf/utt nilai server-rendered  -> "browser up to date..." (generic)
     - kirim nilai fingerprint simulasi       -> lolos check fingerprint,
                                                 berhenti di check VPN/IP
     Jadi urutan validasi server: csrf -> captcha -> fingerprint -> IP reputation.

SOLUSI YANG REALISTIS:
  a. Jalankan dari IP seluler/hotspot (mobile=true, hosting=false)
     -> paling mungkin lolos tanpa melanggar kebijakan.
  b. IP dinamis ISP? restart router utk dapat blok IP lain.
  c. Resi proxy: melanggar ToS situs + risiko auto-ban -> tidak disarankan.
